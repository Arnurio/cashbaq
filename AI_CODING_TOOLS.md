## ЧАСТЬ 1 — ПРОЕКТ ДЛЯ АГЕНТА

### Что такое Cashbaq

Мобильное приложение для жителей Казахстана: пользователь добавляет свои банковские карты → выбирает категорию покупки (продукты, рестораны, топливо...) → приложение показывает, какой картой выгоднее платить, сколько кэшбэка вернётся.

**Рынок:** Казахстан, русскоязычный интерфейс  
**Монетизация:** бесплатно, без рекламы, без подписки  
**MVP:** нет авторизации, карты хранятся локально на устройстве

### Архитектура одной фразой

```
Expo mobile app  ←→  Supabase (PostgreSQL)  ←→  Vite admin panel
```

Три независимые части:
- `./` — React Native / Expo (мобилка, основной продукт)
- `admin/` — отдельный Vite 8 + React 19 app (для меня, локально)
- Supabase проект `cdtnvqlxsbwcdiapbdkh` — единственный бэкенд

### Монорепо-ловушка

**Это НЕ классический монорепо.** В корне есть `package.json` для Expo, внутри `admin/` — свой `package.json` для Vite. Они не связаны через workspace. Агент должен понимать:

```bash
# Мобилка
npm install         # в корне
npx expo start

# Админка — ОТДЕЛЬНО
cd admin && npm install && npm run dev
```

**Никогда не запускать `npm install` из корня ожидая, что это установит зависимости admin/ — не установит.**

### Критические файлы — трогать осторожно

| Файл | Почему важен | Что сломается если не понять |
|------|-------------|------------------------------|
| `lib/supabase.ts` | SafeStorage обёртка (try/catch) | Web и Expo Go сломаются без try/catch |
| `lib/types.ts` | Все TypeScript типы | Изменение типа = правки в 10+ файлах |
| `lib/cashback.ts` | Бизнес-логика кэшбэка | Неправильный расчёт = неверные рекомендации |
| `lib/constants.ts` | 10 категорий покупок | Они же в БД, изменение = рассинхрон |
| `lib/useData.ts` | Глобальное состояние | Неправильный subscribe = бесконечные ре-рендеры |
| `app/_layout.tsx` | Root layout, шрифты, ErrorBoundary | Сломанный layout = белый экран |

### Структура БД (Supabase)

```
banks          — 7 банков Казахстана с конфигом кэшбэка
bank_rates     — bank_id + category_id → rate (ставка в %)
promos         — промо-акции банков
tips           — советы по кэшбэку (заголовки)
tip_items      — пункты советов (FK → tips)
user_cards     — карты пользователя (RLS: только свой user_id)
rate_reports   — жалобы пользователей на неточные ставки
```

**RLS политики:**
- `banks`, `bank_rates`, `promos`, `tips`, `tip_items` — публичный SELECT; INSERT/UPDATE/DELETE открыты для админки
- `user_cards` — только владелец (`auth.uid() = user_id`)
- `rate_reports` — публичный INSERT (любой может отправить); SELECT только через сервис

### Типы кэшбэка — это core бизнес-логика

Агент ОБЯЗАН понять это перед любой правкой `lib/cashback.ts`:

```
fixed       — фиксированная ставка за категорию (Kaspi*, Halyk, Jusan, Bereke)
selectable  — пользователь выбирает 3 категории (Forte, BCC)
leveled     — ставка зависит от уровня карты + NFC (Freedom)
```

*️⃣ Kaspi Gold — исключение: у него нет фиксированных категорий, только промо-акции. Это техдолг. Не трогай логику Kaspi без явного задания от меня.

### Запрещённые действия (HARD NO)

1. **Обновлять Expo SDK** — только с моего явного разрешения. SDK обновление = 2-3 часа migration.
2. **Деплоить admin/** — adminка только локально, содержит ключи и прямой доступ к БД.
3. **Использовать AsyncStorage напрямую** — только через `lib/storage.ts` (он использует SafeStorage).
4. **Импортировать mobile-компоненты в admin/** или наоборот — они разные рантаймы.
5. **Менять RLS политики** без понимания последствий — можно открыть данные пользователей.
6. **Использовать `lucide-react` в мобилке** — нужен `lucide-react-native`. И наоборот для admin/.

## ЧАСТЬ 2 — GOOGLE JULES

### Что такое Jules

[jules.google.com](https://jules.google.com) — асинхронный AI-агент от Google (работает на базе Gemini). Ты создаёшь задачу, Jules уходит работать в фоне (5-20 минут), возвращается с готовым PR. Идеален для чётко определённых задач.

**Отличие от Claude Code:** Jules асинхронный — ты не ведёшь диалог, ты даёшь задание и ждёшь результат.

### Шаг 1 — Авторизация и подключение репозитория

1. Перейди на [jules.google.com](https://jules.google.com)
2. Войди через Google аккаунт (используй тот же, что у тебя в GitHub)
3. Нажми **"Connect GitHub"** → авторизуй OAuth
4. В списке репозиториев найди `Arnurio/cashbaq`
5. Нажми **"Install Jules GitHub App"** → выбери `Arnurio/cashbaq` (не весь аккаунт)
6. Jules теперь видит репозиторий и может создавать ветки/PR

**Проверка:** в Settings → GitHub → Installed Apps должен появиться Jules.

### Шаг 2 — Создание задачи для Jules

Jules работает через **Issues** или через свой интерфейс. Есть два способа:

#### Способ A: Через интерфейс Jules (рекомендуется)

1. На jules.google.com нажми **"New Task"**
2. Выбери репозиторий `Arnurio/cashbaq`
3. Укажи базовую ветку: `main`
4. Заполни описание задачи (подробнее — в разделе ниже)
5. Jules создаст ветку `jules/[название]` и откроет PR

#### Способ B: Через GitHub Issues

1. Создай Issue в репозитории [Arnurio/cashbaq](https://github.com/Arnurio/cashbaq)
2. Назначь в Labels: `jules`
3. Jules автоматически подберёт задачу (если App установлен)

### Шаг 3 — Как писать задачи для Jules

Jules читает репозиторий, но хорошая задача экономит его время и уменьшает ошибки. **Шаблон:**

```markdown
## Контекст проекта
Cashbaq — кэшбэк-оптимизатор для банков Казахстана.
Стек: Expo 54 + React Native + TypeScript + Supabase.
Прочитай CLAUDE.md для полного контекста.

## Задача
[Конкретное описание: что нужно сделать]

## Файлы для изменения
- [файл 1] — [что изменить]
- [файл 2] — [что изменить]

## Файлы НЕ трогать
- lib/supabase.ts (SafeStorage обёртка — критична)
- app/_layout.tsx (Root layout)
- admin/ (только если задача явно про admin)

## Ожидаемый результат
[Что должно работать по-другому после изменения]

## Проверка
npx jest && npx tsc --noEmit — оба должны пройти без ошибок.
```

### Шаг 4 — Что делать с PR от Jules

Jules откроет PR в ветку `main`. Твои шаги:

1. **Проверь изменения:** `git checkout jules/branch-name && git diff main...`
2. **Запусти тесты:** `npx jest` (Jules иногда забывает их обновить)
3. **Проверь TypeScript:** `npx tsc --noEmit`
4. **Открой мобилку:** `npx expo start --web` — проверь визуально
5. Если всё ок → **Merge** через GitHub UI

### Ограничения Jules (важно знать)

| Ограничение | Что делать |
|-------------|-----------|
| Не понимает Expo-специфику хорошо | Указывай явно: "это Expo, не Web React" |
| Может нарушить структуру expo-router | Проверяй app/ структуру после его PR |
| Не знает наш SafeStorage паттерн | Напиши в задаче: "используй lib/storage.ts, не AsyncStorage" |
| Может импортировать lucide-react вместо lucide-react-native | Явно указывай в задаче |
| Не обновит тесты автоматически | Добавляй "обнови тесты в lib/__tests__/" в задачу |
| Иногда создаёт лишние файлы | Проверяй `git status` перед merge |

### Хорошие задачи для Jules (Jules справится отлично)

- Добавить поле в existing форму (admin/src/pages/*.tsx)
- Написать SQL миграцию по описанию
- Добавить новую категорию в lib/constants.ts + синхронизировать
- Рефакторинг одного компонента без изменения API
- Добавить тесты для уже написанной логики
- Перевести hardcoded строки в константы
- Добавить обработку ошибок в конкретную функцию

### Плохие задачи для Jules (лучше делать самому или с Claude Code)

- "Добавь авторизацию" — слишком широко, затрагивает 10+ файлов
- "Обнови дизайн главного экрана" — требует понимания RN StyleSheet
- "Разберись почему кэш не инвалидируется" — нужен диалог с агентом
- "Мигрируй Expo SDK" — категорически нельзя делать автономно
- Любые изменения в RLS политиках без явной инструкции

## ЧАСТЬ 3 — ДРУГИЕ AGENTIC CODING TOOLS

### Cursor и Windsurf (IDE-агенты)

Оба работают как IDE с встроенным AI. Читают файлы локально.

**Для Cursor:**

1. Открой папку проекта в Cursor
2. Cursor автоматически читает `CLAUDE.md` (он понимает этот файл)
3. Создай `.cursorrules` в корне:

```
# .cursorrules для Cashbaq
Читай CLAUDE.md для полного контекста проекта.
Это Expo React Native + TypeScript проект.
admin/ — отдельный Vite app, не смешивай импорты.
Используй lucide-react-native для мобилки, lucide-react для admin/.
Всегда используй lib/storage.ts вместо AsyncStorage напрямую.
Интерфейс на русском языке.
После изменений запускай: npx jest && npx tsc --noEmit
```

**Для Windsurf:**

Аналогично, создай `.windsurfrules`:

```
# .windsurfrules для Cashbaq
[тот же текст что в .cursorrules]
```

Windsurf также поддерживает `AGENTS.md` — он читает его автоматически как правила.

### GitHub Copilot Workspace

Работает через GitHub Issues. Сопоставимо с Jules по механике.

**Как использовать:**

1. Убедись что у тебя подключён Copilot Enterprise или Copilot Individual с Workspace preview
2. Создай GitHub Issue с детальным описанием (шаблон такой же как для Jules выше)
3. В Issue нажми **"Open in Copilot Workspace"**
4. Copilot предложит план → ты утверждаешь → он реализует → PR

**Отличие от Jules:** Copilot Workspace интерактивный — ты утверждаешь каждый шаг плана перед выполнением.

### Devin (Cognition AI)

Devin — полностью автономный агент, работает в облачной VM. Самый мощный из автономных, но и самый дорогой.

**Как подключить:**

1. Зарегистрируйся на [devin.ai](https://devin.ai)
2. Подключи GitHub: Settings → Integrations → GitHub
3. Выбери репо `Arnurio/cashbaq`
4. Создай сессию с полным контекстом

**Шаблон первого сообщения Devin:**

```
Ты работаешь над проектом Cashbaq — кэшбэк-оптимизатор для банков Казахстана.

Прочитай эти файлы в начале сессии:
1. CLAUDE.md — полный контекст проекта
2. AI_CODING_TOOLS.md — правила для агентов (ты сейчас читаешь его)
3. HANDOFF.md — текущее состояние проекта

Стек: Expo SDK 54 + React Native + TypeScript + Supabase + Vite admin.

Критические правила:
- НЕ обновлять Expo SDK
- Использовать lib/storage.ts, не AsyncStorage напрямую
- admin/ — отдельный Vite app, отдельные зависимости
- Интерфейс на русском
- После изменений: npx jest && npx tsc --noEmit

Задача: [твоя задача здесь]
```

**Devin хорошо справляется с:** большими фичами, которые требуют изменений в 5+ файлах, когда у тебя есть время подождать 20-30 минут.

### Aider (CLI-агент)

Open source CLI инструмент. Работает локально, читает файлы которые ты ему передаёшь.

**Установка и запуск:**

```bash
pip install aider-chat

# Запуск с контекстом проекта
aider --model claude-3-5-sonnet \
      CLAUDE.md lib/types.ts lib/cashback.ts \
      --message "Добавь поддержку новой категории 'home' в типы и бизнес-логику"
```

**Правило:** всегда передавай `CLAUDE.md` первым аргументом — это даёт агенту весь контекст.

**Полезные флаги:**

```bash
aider --yes-always     # не спрашивать подтверждения каждого изменения
aider --no-git         # не делать автоматический commit
aider --test-cmd "npx jest"  # запускать тесты после каждого изменения
```

### Claude Code (текущий инструмент)

Уже настроен. Читай `CLAUDE.md` и `HANDOFF.md`. Структура работы через несколько Claude Code окон описана в `AGENTS.md`.

## ЧАСТЬ 4 — УНИВЕРСАЛЬНЫЕ ПРАВИЛА ДЛЯ ЛЮБОГО АГЕНТА

Эти правила применимы к Jules, Devin, Cursor, Windsurf, и любому другому инструменту.

### Правило 1: Читай CLAUDE.md первым

Это не опционально. CLAUDE.md содержит:
- Структуру файлов
- Суть бизнес-логики
- Команды запуска
- Список банков и типов кэшбэка
- Правила работы

Без прочтения CLAUDE.md агент делает ошибки на базовом уровне.

### Правило 2: Зоны ответственности

Чтобы не создавать конфликты при одновременной работе нескольких агентов:

| Зона | Файлы | Примечание |
|------|-------|-----------|
| Данные / API | `lib/api.ts`, `lib/types.ts`, `lib/cashback.ts` | Изменение types.ts = каскадные правки |
| Мобильные экраны | `app/(tabs)/`, `app/find.tsx`, `app/add-card.tsx`, `app/card-detail.tsx` | expo-router: файл = маршрут |
| Инфраструктура | `lib/supabase.ts`, `lib/storage.ts`, `lib/useData.ts` | Самые критичные файлы |
| Admin panel | `admin/src/` | Отдельная экосистема |
| База данных | `supabase/migrations/` | Нумерация миграций строго по порядку |

### Правило 3: Ветки и коммиты

```bash
# Формат ветки
feature/[краткое-название]    # новая фича
fix/[что-фиксируем]           # исправление бага
jules/[название]              # Jules создаёт автоматически
devin/[название]              # Devin создаёт автоматически

# Формат коммита
feat: добавить фильтр по банку в admin
fix: исправить расчёт кэшбэка для Freedom leveled
refactor: выделить логику SafeStorage в отдельный модуль
test: добавить тесты для cashback.ts leveled type
```

### Правило 4: Проверка перед PR

Обязательный чеклист для любого агента перед созданием PR:

```bash
npx jest                    # все 59+ тестов зелёные
npx tsc --noEmit            # TypeScript без ошибок
npx expo start --web        # запускается без white screen
cd admin && npm run build   # admin собирается без ошибок
git diff main --stat        # проверь что не изменил лишних файлов
```

### Правило 5: Что писать в PR description

```markdown

- [конкретные изменения]

## Затронутые файлы
- [список файлов]

## Тесты
- [ ] npx jest — X/X прошло
- [ ] npx tsc --noEmit — чисто
```
