- Мобильные приложения банков (часто только там полная картина)
- PDF-условия

**Полная автоматизация невозможна.** Решение — гибридный подход:
1. Ручное обновление через `admin/` (старт)
2. Краудсорсинг от пользователей (после набора аудитории)
3. Скрапинг того, что можно (опционально, позже)

## РЕВИЗИЯ МАЯ 2026 — ПОЧЕМУ СОКРАЩАЕМ ДО 3 БАНКОВ

### Что обнаружено
Все 24 ставки в `bank_rates` и описания 7 банков в `lib/bankData.ts` сгенерированы AI-агентами в предыдущих сессиях. Ни одна не сверена с реальным личным кабинетом банка. Источники: общие знания модели (могут быть устаревшими), маркетинговые тексты с сайтов ("до 15%" ≠ реальный кэшбэк), повторяющиеся правки AI без валидации.

### Почему это критично
Cashbaq как продукт построен на **доверии к ставкам**. Дезинформация = пользователь получит меньше кэшбэка чем ожидал = удалит приложение и оставит 1 звезду. Это нарушает Принцип №1 ("лучше отсутствие данных, чем ложные") и Анти-паттерн №1 ("не запускаемся с фейковыми данными").

### Решение

**1. На запуске активны только 3 банка:**
- Kaspi Bank
- Halyk Bank
- Freedom Bank

У владельца проекта есть личные счета в этих банках → ставки можно проверить лично из приложения банка.

**2. Forte, BCC, Bereke, Alatau City → деактивируются (`is_active=false`)**
Данные сохраняются в БД, но не показываются в UI. Возвращаются по одному, когда появится надёжный источник.

### Иерархия достоверности (новый стандарт)

| Уровень | Источник | `verified_by` | UX-маркер |
|---|----|----|----|
| 🟢 **A** | Скрин/скриншот из ЛК банка владельцем/командой | `user` | "Проверено DD.MM.YYYY" |
| 🟡 **B** | Краудсорсинг (`rate_reports`) с подтверждением | `community` | "Со слов пользователей" |
| 🟠 **C** | Скриншот публичной страницы банка | `bank_site` | "По данным forte.kz" + ссылка |
| 🔴 **D** | AI / эвристика | `ai_estimate` | **Скрыто из UI** |

**Правило:** ставка показывается в основной выдаче только если `verified_by IN ('user','bank_site')` И не старше 90 дней.

### Изменения в схеме

```sql
ALTER TABLE bank_rates ADD COLUMN verified_by text DEFAULT 'ai_estimate'
  CHECK (verified_by IN ('user','community','bank_site','ai_estimate'));
ALTER TABLE bank_rates ADD COLUMN verified_at timestamptz;
ALTER TABLE bank_rates ADD COLUMN verified_note text;
ALTER TABLE banks      ADD COLUMN is_active   boolean DEFAULT true;
```

### Условия возврата скрытых банков

Банк возвращается в активные (`is_active=true`) когда:
1. Получен скрин из ЛК банка от пользователя/команды → `verified_by='user'`
2. ИЛИ есть подтверждённый источник на сайте банка → `verified_by='bank_site'`
3. ИЛИ ≥3 community-репорта с одинаковыми ставками → `verified_by='community'`

До тех пор — банк помечается на лендинге как "Скоро" с ссылкой "напомнить когда добавим".

## ПРИНЦИПЫ

1. **Лучше отсутствие данных, чем ложные данные.** Если ставка не подтверждена — показывать "Уточняется".
2. **Прозрачность важнее красоты.** Дата обновления и источник на каждой ставке.
3. **Сначала качество, потом масштаб.** Не запускаем в Store пока ставки не выверены.
4. **Краудсорс — после доверия.** Сначала база юзеров поверит данным, потом сами начнут присылать.
5. **Не торопимся с монетизацией.** Бесплатно и без рекламы — конкурентное преимущество.

## АНТИ-ПАТТЕРНЫ (чего не делаем)

- ❌ Не запускаемся "как есть" с фейковыми данными — убьёт репутацию
- ❌ Не вкладываемся в маркетинг до готовности данных
- ❌ Не добавляем фичи, которые не двигают к цели "доверие + рост"
- ❌ Не делаем партнёрства с банками рано — нечего предложить без аудитории
- ❌ Не обновляем Expo SDK ради новых фич — стабильность важнее
