# AGENTS.md — Управление командой AI-агентов

> Этот файл — доска задач для команды агентов.
> ДИРИЖЁР обновляет его. Агенты читают свою секцию и работают только в ней.

---

## КТО ДИРИЖЁР

Дирижёр — это **первый агент** (аккаунт №1, главное окно).
Он не пишет код сам — он:
1. Читает этот файл
2. Назначает задачи остальным агентам (обновляет секцию ЗАДАЧИ)
3. Делает `git merge` веток когда агент сообщает о готовности
4. Разрешает конфликты
5. Проверяет итог

Промпт для дирижёра:
```
Ты дирижёр команды агентов проекта Cashbaq. Прочитай CLAUDE.md и AGENTS.md.
Твоя задача: [ОПИСАНИЕ БОЛЬШОЙ ЗАДАЧИ].
Декомпозируй её на подзадачи для агентов, обнови секцию ЗАДАЧИ в AGENTS.md,
затем скажи мне что написать каждому агенту.
```

## ПРАВИЛА ДЛЯ КАЖДОГО АГЕНТА

### При старте работы
```bash
git pull origin main          # забери последнее
git checkout -b feature/agentN  # создай свою ветку (N = твой номер)
```

### В процессе работы
- Работай **только в своих файлах** (см. колонку "Файлы" в таблице выше)
- Не трогай файлы других агентов
- Коммить после каждого завершённого шага:
  ```bash
  git add [свой файл]
  git commit -m "AgentN: описание что сделано"
  ```

### Когда задача готова
```bash
git push origin feature/agentN
```
Потом напиши дирижёру: **"Агент-N готов. Ветка feature/agentN запушена."**

---

## ПРАВИЛА ДИРИЖЁРА

### Как принять работу агента
```bash
git fetch origin
git checkout feature/agentN
# проверь код
git checkout main
git merge feature/agentN
git push origin main
```

### Как раздать новые задачи
1. Обнови таблицу ЗАДАЧИ выше
2. Скажи каждому агенту:
   ```
   git pull origin main
   Твоя новая задача: [задача]
   Файлы: [список файлов]
   ```

## ЗОНЫ ОТВЕТСТВЕННОСТИ (защита от конфликтов)

Каждый агент работает в своей зоне. Это предотвращает конфликты при merge.

| Зона | Файлы | Кому |
|------|-------|------|
| Бэкенд/данные | `lib/api.ts`, `lib/types.ts`, `lib/cashback.ts`, `lib/useData.ts` | Агент-1 |
| Экраны/UI | `app/(tabs)/`, `app/find.tsx`, `app/add-card.tsx` | Агент-2 |
| Инфраструктура | `lib/supabase.ts`, `lib/storage.ts`, `admin/` | Агент-3 |
| Merge + review | всё | Дирижёр |

> Нужен другой раздел задач? Дирижёр перераспределяет зоны в начале спринта.

## ПРИМЕР СЕССИИ (как выглядит реальная работа)

```
[ДИРИЖЁР — аккаунт №1]

  Агент-1: Добавить Supabase Auth в lib/supabase.ts + lib/storage.ts

git pull && git checkout -b feature/agent1
"Добавь Supabase Auth в lib/supabase.ts..."
→ коммит → пуш → "Готово, ветка feature/agent1 запушена"

[АГЕНТ-2 — аккаунт №3]
git pull && git checkout -b feature/agent2
"Создай экран логина app/login.tsx..."
→ коммит → пуш → "Готово, ветка feature/agent2 запушена"

[ДИРИЖЁР]

git merge feature/agent2  # принять работу агента-2
```
