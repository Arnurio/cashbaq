# SUBAGENTS.md — Субагенты и параллельная работа

> Этот файл — для оркестратора и для агентов, которые хотят делегировать исследование.
> Субагент = агент внутри агента. Делает поиск / анализ, возвращает компактный результат.
>
> Связанные файлы: [ORCHESTRATOR.md](ORCHESTRATOR.md) · [AGENTS.md](AGENTS.md)

---

## ЗАЧЕМ СУБАГЕНТЫ

**Проблема:** при исследовании кода главный контекст агента заполняется инструментами поиска. После 50 вызовов grep/read — контекст на 60%, медленнее, дороже.

**Решение:** делегировать поиск субагенту. Он работает в своём контексте, возвращает сжатый результат. Главный контекст остаётся чистым.

```
Без субагентов:
  Агент → grep → read → grep → read → grep → read → [контекст 70%]

С субагентом:
  Агент → "найди все места где используется UserCard"
              → Субагент (отдельный контекст)
                  → grep × 10 → read × 5 → return list
              → Агент получает: "UserCard используется в 6 файлах: [список]"
  Агент → [контекст 20%]
```

## ТИПЫ СУБАГЕНТОВ (Claude Code)

### Explore — поиск по кодовой базе

Лучший выбор для: найти файлы, найти использования, понять структуру.

```
Промпт для Explore субагента:
"Найди все файлы где импортируется UserCard из lib/types.ts.
Верни список файлов с номерами строк. Не меняй код."
```

### general-purpose — сложный анализ

Лучший выбор для: понять как работает фича, проанализировать данные, исследовать внешние ресурсы.

```
Промпт для general-purpose субагента:
"Проанализируй lib/cashback.ts (строки 1-150).
Опиши что делает каждая публичная функция и какие edge cases не обработаны.
Не меняй код."
```

## КОГДА ИСПОЛЬЗОВАТЬ СУБАГЕНТОВ

### Используй субагента когда:

| Ситуация | Тип субагента |
|----------|---------------|
| "Где используется X?" | Explore |
| "Какие файлы затрагивает фича Y?" | Explore |
| "Как устроена логика Z?" | general-purpose |
| "Какие тесты покрывают модуль A?" | Explore |
| "Что изменилось в ветке B?" | general-purpose |
| "Найди все TODO в кодовой базе" | Explore |

### НЕ используй субагента когда:

- Задача требует написания/изменения кода — субагент только читает
- Ответ очевиден из названия файла
- Нужна 1 команда grep — сделай сам

## ШАБЛОНЫ ПРОМПТОВ ДЛЯ СУБАГЕНТОВ

### Найти использования символа

```
Используй subagent Explore.
Найди все файлы в проекте Cashbaq где упоминается [СИМВОЛ].
Включи: путь к файлу и номер строки.
Исключи: node_modules, .git, *.lock.
Не меняй код.
```

### Понять как работает модуль

```
Используй subagent general-purpose.
Прочитай файл [ПУТЬ].
Ответь на вопросы:
1. Что этот модуль делает (3 предложения)?
2. Какие функции публичные?
3. От чего зависит (импорты)?
4. Что зависит от него (если знаешь)?
Не меняй код.
```

### Аудит тестового покрытия

```
Используй subagent Explore.
Найди все тестовые файлы в lib/__tests__/.
Для каждого файла — что тестируется (один файл описывает один модуль).
Верни: список модулей + покрыты ли тестами (да/нет).
```

### Поиск технического долга

```
Используй subagent general-purpose.
Найди в кодовой базе:
1. Комментарии TODO / FIXME / HACK / TEMP
2. Файлы с типом 'any' в TypeScript
3. Функции длиннее 80 строк
4. Закомментированный код

Верни: путь + строка + текст. Не меняй код.
```

## ПАРАЛЛЕЛЬНАЯ РАБОТА АГЕНТОВ

Когда задачи **независимы** (не трогают одни файлы), запускай агентов параллельно.

### Независимость = безопасно параллелить

```
Задача: Добавить новую категорию "Home"

Агент-1 (lib/): добавить в lib/constants.ts + lib/types.ts
Агент-2 (app/): обновить UI на app/(tabs)/index.tsx
Агент-3 (admin/): добавить в admin/src/pages/Categories.tsx
Агент-4 (db/): написать SQL миграцию в supabase/migrations/

→ Агент-1 и Агент-4 независимы — запускать параллельно
→ Агент-2 зависит от Агент-1 (нужен новый тип) — запускать после
→ Агент-3 независим от всех — запускать параллельно с 1 и 4
```

### Граф зависимостей для Cashbaq

```
lib/types.ts         ← базовый, все зависят
     ↓
lib/api.ts           ← зависит от types
lib/cashback.ts      ← зависит от types
     ↓
lib/useData.ts       ← зависит от api
     ↓
app/* screens        ← зависят от useData
     ↓
admin/               ← независим от всех остальных
```

**Правило:** если Агент-X меняет тип в `lib/types.ts`, все остальные агенты должны ждать его merge перед стартом.

## АНТИПАТТЕРНЫ СУБАГЕНТОВ

### Не давай субагенту слишком широкое задание

```
❌ Плохо:
"Проанализируй весь проект и найди все проблемы"
→ Субагент потратит весь контекст, вернёт общий список

✅ Хорошо:
"Найди все места где вызывается AsyncStorage напрямую (не через SafeStorage)"
→ Конкретный результат: 3 файла, 7 строк
```

### Не давай субагенту задачи с изменением кода

```
❌ Плохо:
"Найди и исправь все TypeScript ошибки"
→ Субагент начнёт менять код, создаст конфликты

✅ Хорошо:
"Найди файлы где TypeScript выдаёт ошибки (запусти tsc --noEmit)"
→ Список файлов → главный агент сам исправляет
```

### Не вкладывай субагентов в субагентов

Максимальная глубина: 2 уровня (агент → субагент). Больше — запутанно и дорого.

## РЕЗУЛЬТАТ СУБАГЕНТА → ДЕЙСТВИЕ ГЛАВНОГО АГЕНТА

```
[Субагент вернул]: "UserCard используется в 6 файлах:
  - app/(tabs)/cards.tsx:42
  - app/card-detail.tsx:18
  - lib/cashback.ts:25
  - lib/storage.ts:14
  - lib/useData.ts:67
  - lib/__tests__/api.test.ts:8"

[Главный агент делает]:
  1. Определяет какие файлы нужно изменить для задачи
  2. Читает только нужные строки (не все файлы целиком)
  3. Планирует изменения
  4. Назначает рабочим агентам конкретные файлы
```

## МЕТРИКИ ЭФФЕКТИВНОСТИ

| Метрика | Без субагентов | С субагентами |
|---------|---------------|---------------|
| Использование контекста на исследование | 40-60% | 5-10% |
| Точность найденных файлов | 70% (угадывание) | 95% (реальный поиск) |
| Конфликты при merge | Высокие | Низкие (полный список файлов) |
| Скорость | Быстрее запуск | Быстрее финиш |

**Вывод:** для задач с >3 неизвестными файлами — субагент окупается всегда.
